# Лучшие практики ent

## 1. Не используйте `Schema.Create` в продакшене

Используйте `atlas` для версионирования миграций.

## 2. Всегда закрывайте клиент

```go
defer client.Close()
```
## 3. Используйте eager loading для избежания N+1
`With...()` уменьшает количество запросов. Мониторьте SQL через драйвер логирования.

## 4. Ограничивайте размер выборки
Используйте `Limit`, `Offset`, `Where` — не выгружайте всю таблицу.

## 5. Используйте контекст с таймаутом
```go
ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
defer cancel()
```
## 6. Держите схемы в отдельном пакете
Структура пакета `ent/schema` — стандарт. Не кладите туда бизнес-логику.

## 7. Для продакшена включайте prepared statements
При открытии коннекта передавайте опцию `ent.UsePreparedStmt()`.

## 8. Проверяйте `ent.IsNotFound(err)` и другие констрейнты
Никогда не паникуйте на ошибке, если она ожидаема.

## 9. Пишите хуки для инвариантов
Например, проверка возраста > 0 через `OnCreate`.

## 10. Тестируйте с реальной БД
Используйте `enttest.Open` с in-memory SQLite для юнит-тестов.
