# Лучшие практики SQLBoiler

## 1. Генерируйте модели как часть сборки

Добавьте в CI: `sqlboiler psql`. Проверяйте, что сгенерированный код не расходится с БД.

## 2. Не редактируйте сгенерированные файлы

Вся настройка — через `sqlboiler.toml`. Модели пересоздаются при каждой генерации.

## 3. Используйте `boil.SetDB` или внедряйте зависимость

Для простых проектов — глобальный `boil.SetDB`. Для тестируемых — передавайте `*sql.DB` явно.

## 4. Не забывайте про контекст

Все методы принимают `context.Context`. Используйте таймауты.

## 5. Eager Loading vs отдельные запросы

Используйте `qm.Load` для предзагрузки связанных данных, чтобы избежать N+1.

## 6. Для массовых вставок используйте слайсы

```go
var users models.UserSlice
users = append(users, &models.User{...})
users.InsertAll(ctx, db, boil.Infer())
```
## 7. Настройте логирование
SQLBoiler использует `boil.DebugMode = true` для вывода SQL в stdout. Для продакшена используйте кастомный логгер через `boil.SetDB`.

## 8. Используйте `Whitelist`/`Blacklist` в `sqlboiler.toml`
Явно указывайте, какие таблицы генерировать, чтобы не засорять код.

## 9. Тестируйте с реальной БД в Docker
Используйте `testcontainers-go` с PostgreSQL для интеграционных тестов.

## 10. Версионируйте схему БД
SQLBoiler работает с готовой схемой. Храните миграции в репозитории (golang-migrate, Atlas).
