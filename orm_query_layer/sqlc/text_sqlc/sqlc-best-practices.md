# Лучшие практики sqlc

## 1. Храните схему и запросы в репозитории

`schema.sql` и `queries.sql` — это исходники. Генерированный код коммитить или нет — вопрос договорённости (лучше коммитить, чтобы не зависеть от установленного `sqlc` при CI).

## 2. Проверяйте генерацию в CI

```bash
sqlc generate
git diff --exit-code
```
Гарантирует, что сгенерированный код соответствует SQL.

## 3. Используйте `pgx/v5` для PostgreSQL
Он даёт лучшую производительность и больше возможностей (COPY, batch).

## 4. Разделяйте запросы по сущностям
* `queries/users.sql`
* `queries/orders.sql`
Так проще ориентироваться.

## 5. Пишите осмысленные имена для параметров
Используйте `sqlc.arg` для ясности, особенно в сложных запросах.

## 6. Тестируйте с реальной БД
Используйте `testcontainers-go` с PostgreSQL, поднимайте схему через `schema.sql` и тестируйте сгенерированные функции.

## 7. Не бойтесь сложных SQL
sqlc поддерживает оконные функции, CTE, агрегаты, JOIN. Пишите оптимальный SQL.

## 8. Используйте `emit_interface` для мокирования
Генерация интерфейса `Querier` позволяет мокировать слой БД в юнит-тестах (руками или через mockgen).

## 9. Для сложной бизнес-логики оборачивайте в репозиторий
Не используйте сгенерированные функции напрямую в обработчиках HTTP. Создайте слой `repository`, который принимает `Querier`.

## 10. Следите за обновлениями sqlc
Инструмент активно развивается, появляются новые фичи (поддержка sqlc-gen-python, удалённая кодогенерация и т.д.).
