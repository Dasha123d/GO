# Лучшие практики Jaeger + OpenTelemetry

## 1. Всегда завершайте спаны

Используйте `defer span.End()`.

## 2. Передавайте контекст

Не теряйте `context.Context` при вызовах между слоями.

## 3. Используйте сэмплирование в продакшене

10-100% в зависимости от трафика. `ParentBased(TraceIDRatioBased(0.1))`.

## 4. Не перегружайте атрибуты

Логируйте только нужные для поиска и отладки поля. Не помещайте тела запросов целиком.

## 5. Инструментируйте все внешние вызовы

HTTP-клиенты, gRPC, базы данных — используйте готовые плагины (`otelhttp`, `otelgrpc`, `otelsql`).

## 6. Именуйте сервисы единообразно

Имя сервиса должно совпадать с именем в Kubernetes / логах.

## 7. Настройте корреляцию с логами

Добавляйте `trace_id` и `span_id` в логи:

```go
spanCtx := trace.SpanContextFromContext(ctx)
log.WithFields(logrus.Fields{
    "trace_id": spanCtx.TraceID().String(),
    "span_id":  spanCtx.SpanID().String(),
}).Info("message")
```
## 8. Мониторьте Jaeger Collector
Если коллектор недоступен, экспортер накапливает спаны в памяти. Настройте алерты.

## 9. Тестируйте с Jaeger All-in-One в CI
Поднимайте Jaeger в Docker Compose и проверяйте, что спаны доходят.

## 10. Обновляйте OpenTelemetry SDK
Jaeger-экспортер развивается, старые версии могут быть несовместимы с новыми коллекторами.
