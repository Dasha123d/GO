# Лучшие практики Prometheus в Go

## 1. Именование метрик

Следуйте [стандарту](https://prometheus.io/docs/practices/naming/):
- `myapp_requests_total` (суффикс `_total` для счётчиков)
- `myapp_request_duration_seconds` (единицы в названии)
- Используйте `snake_case`.

## 2. Не злоупотребляйте метками

Избегайте высокой кардинальности. Не кладите ID пользователей, email, URL с query-параметрами в метки.

## 3. Всегда регистрируйте метрики в init()

```go
var requestCount = prometheus.NewCounterVec(...)
func init() {
    prometheus.MustRegister(requestCount)
}
```
## 4. Для продакшена используйте отдельный реестр
Особенно в библиотеках — создавайте свой `prometheus.NewRegistry()` и не засоряйте глобальный.

## 5. Используйте `promhttp.Handler` с таймаутом
```go
handler := promhttp.Handler()
http.Handle("/metrics", handler)
```
Не выполняйте тяжёлых вычислений в `Collect()`.

## 6. Гистограммы, а не Summary для распределений
Гистограммы можно агрегировать на серверной стороне, они дешевле.

## 7. Задавайте осмысленные buckets
Не используйте `DefBuckets` для всего. Анализируйте свои данные и настраивайте под диапазон значений.

## 8. Тестируйте метрики
В unit-тестах проверяйте значения метрик после выполнения кода.

## 9. Удаляйте устаревшие метрики
Для короткоживущих объектов используйте `DeleteLabelValues`.

## 10. Мониторьте сам Prometheus
Следите, что `/metrics` отвечает быстро, и количество рядов не растёт бесконечно.
