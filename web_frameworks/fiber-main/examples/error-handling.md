# Обработка ошибок и восстановление

## Философия ошибок в Fiber v3
Все хендлеры и middleware возвращают `error`. Если обработчик возвращает ошибку, Fiber автоматически:
1. Вызывает глобальный обработчик ошибок (если настроен в `fiber.Config`)
2. Возвращает HTTP 500 с текстом ошибки (в development-режиме)
3. Логирует стек вызовов в консоль

## middleware/recover
Критически важен для production. Предотвращает падение сервера при `panic()` в любом месте стека.
- Захватывает панику до того, как она убьёт процесс
- Возвращает 500 Internal Server Error клиенту
- Опционально записывает стек в лог или внешние системы (Sentry, Datadog)

## Кастомная обработка
Можно переопределить `ErrorHandler` в `fiber.Config` для:
- Форматирования JSON-ответов с единой схемой `{success, error, code}`
- Логирования в ELK/Stackdriver
- Скрытия внутренних деталей от клиентов в production

## Связь с кодом
`error-handling.go` показывает:
- Настройку глобального `ErrorHandler`
- Подключение `recover` для защиты от паник
- Разницу между возвратом `error` и вызовом `panic()`
- Безопасную обработку бизнес-ошибок
