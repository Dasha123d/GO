# Middleware и логирование запросов

## Что такое Middleware?
Промежуточные обработчики, выполняемые до/после основного хендлера. Используются для логирования, аутентификации, CORS, сжатия и восстановления после паник.

## Порядок выполнения
1. Запрос поступает в `app.Use(...)`
2. Middleware вызывает `c.Next()` для передачи управления в стек
3. Выполняется следующий middleware или целевой хендлер
4. Управление возвращается обратно в стек middleware (пост-обработка)

## Встроенные middleware
- `logger` — логирование в стиле Express/Nginx
- `recover` — безопасная обработка `panic()`
- `cors` — настройка кросс-доменных запросов
- `compress` — gzip/brotli сжатие ответов

## Особенности
- Middleware можно применять глобально (`app.Use`) или локально (`group.Use`)
- Кастомный middleware должен иметь сигнатуру `func(fiber.Ctx) error`
- `c.Next()` возвращает ошибку от последующих обработчиков, если она возникла

## Связь с кодом
`middleware-logger.go` показывает:
- Подключение стандартного логгера с кастомным форматом
- Создание собственного middleware для замера времени выполнения
- Демонстрацию порядка выполнения и возврата управления
