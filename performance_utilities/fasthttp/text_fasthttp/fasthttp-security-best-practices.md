# Безопасность fasthttp: лучшие практики

## 1. Ограничение размера тела запроса

```go
s := &fasthttp.Server{
    MaxRequestBodySize: 4 << 20, // 4 MB
}
```
Предотвращает исчерпание памяти.

## 2. Защита от медленных клиентов (Slowloris)
Используйте тайм-ауты:
```go
s.ReadTimeout = 10 * time.Second
s.WriteTimeout = 10 * time.Second
s.MaxConnsPerIP = 50
```
Fasthttp также имеет встроенную защиту от очень медленных клиентов (ограничение времени на чтение заголовков).

## 3. Не сохраняйте ссылки на RequestCtx
Поля `RequestCtx` переиспользуются. Копируйте данные, если нужно сохранить их вне обработчика:
```go
body := append([]byte{}, ctx.Request.Body()...)
```
## 4. Защита от HTTP-request smuggling
Fasthttp строго парсит заголовки, но всё равно избегайте неоднозначных `Transfer-Encoding` и `Content-Length`.

## 5. Используйте HTTPS
Запускайте сервер через `ListenAndServeTLS` в production, либо ставьте nginx/caddy перед fasthttp.

## 6. Не выставляйте версию 
```go
s.Name = "" // или своё
```
По умолчанию fasthttp добавляет заголовок `Server: fasthttp`. Уберите или замаскируйте.

## 7. Фильтрация заголовков
Не пропускайте непреднамеренные заголовки (например, `X-Forwarded-For` от ненадёжного источника без валидации).

## 8. Логируйте ошибки
Используйте `s.Logger` для логирования ошибок парсинга запросов и внутренних проблем.

## 9. Обновляйте версию
Fasthttp активно поддерживается, регулярно выходят исправления уязвимостей. Следите за обновлениями.

## 10. Проверка метода
Не допускайте неожиданных методов для конкретных эндпоинтов. Проверяйте `ctx.IsGet()`, `ctx.IsPost()` и т.д.
