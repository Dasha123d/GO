# Тюнинг производительности ants

## Как выбрать размер пула

- Для **CPU-bound** задач — `runtime.NumCPU()` (или чуть больше для скрытия латентности планировщика).
- Для **IO-bound** задач — можно больше, но ограничивайте количеством одновременных соединений (например, 100-500), чтобы не перегрузить сеть/БД.

Формула (эмпирическая):
`poolSize = NumCPU * (1 + ожидаемое_время_ожидания_io / ожидаемое_время_cpu)`

## PreAlloc

Если вы точно знаете рабочую нагрузку, используйте `WithPreAlloc(true)`. Это исключает выделение горутин во время работы.

## ExpiryDuration

Для приложений с переменной нагрузкой (например, веб-сервер) задайте `ExpiryDuration` около 30-60 секунд. Тогда пул сжимается в простое и экономит память.

## Nonblocking против блокировки

- `Nonblocking=false` (по умолчанию): вызов `Submit` блокируется, если все горутины заняты и очередь ожидания заполнена. Это обеспечивает обратное давление (backpressure).
- `Nonblocking=true`: при переполнении сразу возвращает ошибку, вы должны обработать её (например, вернуть HTTP 429).

Для веб-API часто выбирают `Nonblocking`, чтобы не держать соединение бесконечно.

## Бенчмарки

В синтетических тестах ants даёт ~10-кратное ускорение по сравнению с созданием отдельной горутины на задачу, и меньшее потребление памяти. Основной выигрыш — переиспользование горутин и отсутствие аллокаций на задачу.

## Мониторинг

Экспортируйте `Running()`, `Cap()`, `Free()` в Prometheus для отслеживания нагрузки.
