# Лучшие практики gomock

## 1. Всегда вызывайте `ctrl.Finish()`

```go
ctrl := gomock.NewController(t)
defer ctrl.Finish()
```
Это гарантирует, что все зарегистрированные ожидания выполнены.

## 2. Избегайте `AnyTimes` без необходимости
`AnyTimes()` снижает строгость теста. Применяйте только для необязательных вызовов (логирование, метрики).

## 3. Используйте конкретные матчеры
`gomock.Eq(42)` лучше, чем `gomock.Any()`, потому что ловит неверные аргументы.

## 4. Тестируйте поведение, а не реализацию
Мокируйте внешние зависимости, а не внутренние детали. Если тест сильно привязан к последовательности вызовов, возможно, код требует рефакторинга.

## 5. Документируйте сложные ожидания
Объясняйте, зачем нужен `InOrder` или `After`, чтобы следующий разработчик понимал логику.

## 6. Разделяйте настройку и выполнение
Сначала создайте контроллер, мок, ожидания. Затем вызывайте тестируемый код. Не мешайте фазы.

## 7. Используйте `mockgen` в CI
Добавьте шаг проверки актуальности сгенерированных моков, чтобы не было расхождений.

## 8. Не мокируйте стандартную библиотеку
Создавайте адаптеры-интерфейсы вокруг `os.File`, `http.Client`, если нужно их тестировать.

## 9. Для многократного использования выносите создание мока во вспомогательную функцию
```go
func newTestRepo(t *testing.T) *mocks.MockRepository {
    ctrl := gomock.NewController(t)
    return mocks.NewMockRepository(ctrl)
}
```
## 10. Предпочитайте `DoAndReturn` условным `Return` по индексу вызова
Это делает тесты более предсказуемыми и читаемыми.
