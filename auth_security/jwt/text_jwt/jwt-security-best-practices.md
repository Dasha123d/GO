# Безопасность JWT: best practices

## 1. Срок жизни

- Access-токен: **15-30 минут**, максимум 1 час.
- Refresh-токен: **несколько дней** + ротация.

## 2. Ключи

- Никогда не храните в коде. Переменные окружения, HashiCorp Vault, AWS Secrets Manager.
- Разные ключи для access и refresh (можно разные алгоритмы).
- Регулярная ротация ключей (с поддержкой старых публичных ключей для валидации).

## 3. Используйте `jti` и blacklist

Добавляйте уникальный ID в каждый токен (`jti`). При logout сохраняйте `jti` access-токена в blacklist до истечения срока. Проверяйте blacklist в middleware.

## 4. Не доверяйте алгоритму из заголовка

Указывайте ожидаемый алгоритм явно:

```go
token, err := jwt.Parse(tokenStr, func(t *jwt.Token) (interface{}, error) {
    if _, ok := t.Method.(*jwt.SigningMethodHMAC); !ok {
        return nil, fmt.Errorf("неожиданный метод подписи: %v", t.Header["alg"])
    }
    return key, nil
})
```
Это защищает от атаки подмены алгоритма (alg=none).

## 5. Защита от `kid`-инъекций
Если используете `kid` в заголовке для выбора ключа, проверяйте, что `kid` не содержит путей или специальных символов. Используйте белый список или хэш-таблицу.

## 6. Проверяйте `aud` и `iss`
```go
jwt.WithAudience("my-frontend")
jwt.WithIssuer("auth-service")
```
Токен, выпущенный для другого сервиса, не должен приниматься.

## 7. Не кладите секреты в токен
JWT подписан, но не зашифрован (если не используется JWE). Пароли, номера карт, личные данные не должны быть в payload.

## 8. Используйте HTTPS
Токены передаются в заголовках – только TLS.

## 9. Реализуйте механизм отзыва
JWT сам по себе не отзывается, пока не истечёт. Держите серверный список отозванных JTI, проверяйте в middleware. Для критичных систем – короткий срок и blacklist.

## 10. Логирование и мониторинг
Логируйте ошибки валидации, попытки повторного использования refresh-токенов. Это индикаторы атак.
