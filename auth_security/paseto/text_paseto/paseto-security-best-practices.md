# Безопасность Paseto: лучшие практики

## 1. Используйте v4

v4 (XChaCha20-BLAKE2b / Ed25519) обеспечивает лучшую производительность и безопасность. Избегайте v1, а v2/v3 используйте только для обратной совместимости.

## 2. Хранение ключей

- **Local ключи** – храните как секреты окружения, в Vault, AWS Secrets Manager. Никогда не в коде.
- **Private ключи** – то же самое; публичные ключи можно распространять открыто.

Экспортируйте ключи в формат PASERK и храните строку.

## 3. Используйте footer для ротации ключей

Footer не зашифрован и не подписан, в нём можно передать ID ключа (`kid`), чтобы при парсинге выбрать правильный публичный ключ.

```go
footer := []byte("v1.key-2025")
token := paseto.NewToken(claims, footer)
```
При проверке читаем `footer`, подбираем ключ.
## 4. Устанавливайте разумные сроки
Access токен: 15–30 минут
Refresh токен: дни, с обязательной ротацией
## 5. Не доверяйте claims без проверки подписи
Всегда вызывайте `Parse` с правильным ключом. Без ключа токен не может быть проверен (в отличие от JWT с alg=none).
## 6. Implicit Assertions (дополнительная защита)
Paseto поддерживает необязательные implicit assertions – дополнительные данные, которые не входят в токен, но участвуют в проверке подписи/шифрования. Это может быть, например, IP-адрес клиента.
```go
// При создании
token.V4Encrypt(key, paseto.WithImplicit([]byte("192.168.1.1")))
// При проверке обязательно передать те же данные
parsed, err := paseto.Parse(enc, key, paseto.WithImplicit([]byte("192.168.1.1")))
```
## 7. Не храните конфиденциальные данные в незашифрованных public токенах
Public токены только подписаны, но не зашифрованы – содержимое доступно всем. Для конфиденциальности используйте local.

## 8. Обрабатывайте ошибки аккуратно
Не раскрывайте детали ошибок клиенту, логируйте их на сервере.
