# Лучшие практики zerolog

## 1. Всегда завершайте цепочку вызовом `Msg` или `Msgf`

Без `Msg` сообщение не будет записано. Компилятор не предупредит, если вы забудете.

## 2. Используйте глобальный логгер или передавайте как зависимость

Глобальный `log.Logger` удобен для простых проектов, но для тестирования и многомодульности лучше передавать логгер явно.

## 3. Не злоупотребляйте `Dict` для сложных объектов

```go
log.Info().Interface("user", user).Msg("...")
```
Это может быть медленно. Лучше выводить конкретные поля или реализовать интерфейс `zerolog.LogObjectMarshaler`:
```go
func (u User) MarshalZerologObject(e *zerolog.Event) {
    e.Str("name", u.Name).Int("age", u.Age)
}
// использование
log.Info().Object("user", u).Msg("...")
```
## 4. Осторожно с `Fatal` и `Panic`
`Fatal` вызывает `os.Exit(1)`, пропуская `defer`. В большинстве случаев лучше вернуть ошибку наверх.

## 5. Настраивайте сэмплирование в высоконагруженных системах
BurstSampler с разумными параметрами защищает от лавины одинаковых сообщений.

## 6. Добавляйте контекст на уровне запроса
Создавайте дочерний логгер с `request_id`, `user_id` и передавайте его по цепочке вызовов.

## 7. Не логируйте чувствительные данные
Пароли, токены, персональные данные должны быть исключены из логов.

## 8. Следите за временем
Используйте `TimeFieldFormat` для читаемого формата в разработке (`time.RFC3339`) и Unix-формат в production.

## 9. Перехватывайте паники через middleware
Веб-фреймворки должны иметь recovery middleware, который логирует панику и стек.

## 10. Тестируйте логирование
В тестах используйте `zerolog.New(io.Discard)` или перехватывайте вывод через буфер.
