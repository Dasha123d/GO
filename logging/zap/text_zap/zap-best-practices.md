# Лучшие практики zap

## 1. Всегда вызывайте `Sync()`

```go
defer logger.Sync()
```
Иначе буферизованные сообщения могут потеряться при завершении программы.

## 2. Используйте структурированный Logger в продакшене
SugaredLogger — только для прототипов и dev-окружений. Продакшен с высоким RPS должен использовать строгий типизированный интерфейс.

## 3. Не используйте глобальный логгер без необходимости
Передавайте логгер как зависимость, а не через `zap.L()`. Это упрощает тестирование.

## 4. Добавляйте контекстные поля один раз
В начале обработки запроса создайте дочерний логгер с общими полями:
```go
logger := baseLogger.With(zap.String("request_id", rid))
```
И передавайте его вниз по цепочке.

## 5. Избегайте `zap.Any()` для сложных объектов
Реализуйте `zapcore.ObjectMarshaler` или используйте конкретные поля.

## 6. Защищайте дорогие вычисления через Check
```go
if ce := logger.Check(zap.DebugLevel, "тяжёлый лог"); ce != nil {
    ce.Write(zap.Int("count", expensiveCall()))
}
```
Это предотвращает вычисление аргументов, если уровень отключён.

## 7. Настройте сэмплирование для высоконагруженных систем
Сэмплирование предотвращает засорение логов одинаковыми сообщениями и снижает нагрузку.

## 8. Используйте `zapcore.NewCore` для гибкой маршрутизации
Вы можете направить ошибки в отдельный файл, а обычные сообщения — в stdout.

## 9. Следите за временем в кодировщике
По умолчанию в `production` время в формате epoch. Переключите на ISO8601, если это удобнее для чтения.

## 10. Тестируйте логирование
Перехватывайте вывод через `zaptest.NewLogger(t)` или `zap.NewNop()` для тестов.
