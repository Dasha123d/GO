# Лучшие практики Logrus

## 1. Создавайте свой экземпляр логгера

Не используйте глобальный `logrus`. Создайте `log := logrus.New()` и настройте его для приложения. Это облегчает тестирование.

## 2. Выбирайте правильный уровень

- **Trace** – самые детальные сообщения (обычно не на проде).
- **Debug** – отладочная информация.
- **Info** – штатные события.
- **Warn** – нештатные, но не критические.
- **Error** – ошибки, требующие внимания.
- **Fatal** – завершение работы.

Не используйте `Info` для ошибок.

## 3. Используйте структурированные поля, а не форматные строки

Плохо:
```go
log.Infof("Пользователь %s вошёл с IP %s", user, ip)
```
Хорошо:
```go
log.WithFields(logrus.Fields{"user": user, "ip": ip}).Info("Пользователь вошёл")
```
Поля позволяют фильтровать и индексировать логи в системах сбора.

## 4. Оборачивайте ошибки с контекстом
```go
log.WithError(err).WithField("request_id", reqID).Error("Не удалось обработать запрос")
```
## 5. Настройте форматтер для production
Используйте `JSONFormatter` с `FieldMap` для совместимости с системами агрегации (например, переименовать `msg` в `message`).

## 6. Не злоупотребляйте Fatal
`Fatal` вызывает `os.Exit`, что не выполняет defer. Лучше вернуть ошибку наверх.

## 7. Фильтруйте конфиденциальные данные
Не логируйте пароли, токены, персональные данные. Если нужно, напишите кастомный форматтер или хук, маскирующий поля.

## 8. Добавляйте request-id
Через middleware в HTTP-сервере добавляйте уникальный ID запроса в каждый лог, чтобы отслеживать цепочку событий.

## 9. Не создавайте логгеры в цикле
Инициализируйте логгер один раз на старте приложения и передавайте его как зависимость.

## 10. Тестируйте логирование
В тестах можно перехватывать вывод логгера с помощью `log.SetOutput(buffer)` и проверять наличие сообщений.
