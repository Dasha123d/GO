# Безопасность jsoniter: лучшие практики

## 1. Ограничение размера тела запроса

Как и с любым JSON-парсером, используйте `http.MaxBytesReader` или middleware Gin для предотвращения атак на память.

```go
c.Request.Body = http.MaxBytesReader(c.Writer, c.Request.Body, 1<<20) // 1 MB
```
## 2. Экранирование HTML
Убедитесь, что конфигурация имеет `EscapeHTML: true`, если JSON встраивается в HTML. По умолчанию в `ConfigCompatibleWithStandardLibrary` включено.

## 3. Валидация полей
jsoniter не проверяет обязательность полей. Используйте дополнительные валидаторы (например, `go-playground/validator`) после анмаршалинга.

## 4. Не используйте ConfigFastest для ненадёжного ввода
`ConfigFastest` пропускает некоторые проверки для скорости. Если вы парсите JSON из внешнего мира, используйте `ConfigCompatibleWithStandardLibrary`, чтобы избежать паник или некорректного поведения.

## 5. Осторожно с `extra.FuzzyDecoders`
Нечёткий парсинг (строку в число и т.д.) может привести к неочевидной потере точности или неожиданным конвертациям. Включайте только если абсолютно уверены.

## 6. Обновляйте библиотеку
Следите за обновлениями `github.com/json-iterator/go`. Хотя проект считается стабильным, возможны исправления безопасности.

## 7. Не раскрывайте ошибки парсинга
Как и везде, возвращайте клиенту общее сообщение, а детали логируйте.

## 8. Thread-safety
После `Froze()` конфигурация потокобезопасна. Не модифицируйте её в рантайме.

## 9. Используйте `BorrowStream` для высоконагруженных сервисов
Это экономит память и снижает нагрузку на GC.
