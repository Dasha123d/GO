# Безопасность Sonic: лучшие практики

## 1. Защита от инъекций в HTML

По умолчанию Sonic экранирует символы `<`, `>`, `&` при маршалинге (`EscapeHTML: true`). Не отключайте это без необходимости, если JSON возвращается веб-клиенту.

## 2. Защита от больших JSON-атак (DoS)

- Ограничивайте размер входящего JSON на уровне HTTP-сервера (через `http.MaxBytesReader` или middleware Gin).
- Используйте `Decoder` с ограничением глубины. Вручную можно не задавать, но не принимайте безлимитные payloads.
- При работе с AST остерегайтесь глубокой вложенности: установите лимит глубины через `ast.NewParser` с опцией `ast.WithMaxDepth(10)`.

## 3. Не доверяйте неизвестным полям

Используйте `DisallowUnknownFields`, чтобы отвергать JSON с неожиданными полями, если модель строгая:
```go
cfg := sonic.ConfigDefault
cfg.DisallowUnknownFields = true
cfg.Froze()
```
## 4. Валидируйте строки
Включайте `ValidateString` для проверки корректного UTF-8 при анмаршалинге, это предотвратит повреждение данных.

## 5. Потоковая обработка больших файлов
Для очень больших входных данных используйте потоковый `Decoder`, чтобы не загружать весь JSON в память:
```go
dec := sonic.ConfigDefault.NewDecoder(reader)
for dec.More() { ... }
```
## 6. Защита конфигураций
Конфигурации после `Froze()` иммутабельны. Создавайте конфиги фабричным методом и замораживайте один раз. Не изменяйте замёрзшие конфиги через отражение.

## 7. Обновляйте Sonic
Разработчики быстро реагируют на уязвимости (например, `integer overflow`). Используйте последнюю версию и следите за changelog.

## 8. Логируйте ошибки анмаршалинга
Не раскрывайте детали ошибок парсинга клиенту, но обязательно логируйте для отладки.

## 9. Используйте Pretouch в init()
Это не только ускоряет, но и инициализирует внутренние кодеки до обработки запросов, исключая гонки при первом вызове.

## 10. Не передавайте Sensitive данные в логи
При логировании JSON не выводите целиком токены, пароли и приватные поля. Можно написать обёртку, которая маскирует поля перед маршалингом.
